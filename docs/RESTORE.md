# Database Restore Procedure

This runbook covers restoring the Azure Database for PostgreSQL Flexible Server
defined in `infra/main.tf`.

| Setting | Value (from `infra/main.tf`) |
|---|---|
| Server | `psql-save-project-test` |
| Resource group | `save-project-test` |
| Primary region | Sweden Central (`swedencentral`) |
| Backup retention | 35 days (automated, managed by Azure) |
| Geo-redundant backup | Enabled (backups copied to the paired region, Sweden South) |
| Point-in-time recovery | Available for any point within the 35-day retention window |

Network access is private only (`public_network_access_enabled = false`), so the
restored server needs a private endpoint before the application can reach it.

## Prerequisites

- Azure CLI (`az`) signed in with Contributor rights on the `save-project-test` resource group.
- The admin password, from Key Vault (it is generated by `random_password.postgresql_admin`).
- A name for the restored server, e.g. `psql-save-project-test-restore-<yyyymmdd>`.

## 1. Point-in-time restore (same region)

Use this to recover from data corruption or accidental deletion.

1. Choose the restore time (UTC, ISO 8601). It must fall within the last 35 days:
   ```sh
   az postgres flexible-server show \
     --resource-group save-project-test \
     --name psql-save-project-test \
     --query "{earliestRestore: backup.earliestRestoreDate, retention: backup.backupRetentionDays, geo: backup.geoRedundantBackup}"
   ```
2. Restore to a new server:
   ```sh
   az postgres flexible-server restore \
     --resource-group save-project-test \
     --name psql-save-project-test-restore-<yyyymmdd> \
     --source-server psql-save-project-test \
     --restore-time "2026-01-01T10:00:00Z"
   ```
3. Continue with [Post-restore steps](#3-post-restore-steps).

## 2. Geo-restore (regional outage)

Use this when Sweden Central is unavailable. It restores the latest geo-replicated
backup into the paired region. Expect a recovery point objective of up to about 1 hour.

```sh
az postgres flexible-server geo-restore \
  --resource-group save-project-test \
  --name psql-save-project-test-geo-<yyyymmdd> \
  --source-server psql-save-project-test \
  --location swedensouth
```

A geo-restore in another region also needs a VNet, a subnet and a private endpoint in
that region. Then continue with the post-restore steps.

## 3. Post-restore steps

1. Check that the server is up and the data is there:
   ```sh
   az postgres flexible-server show -g save-project-test -n <restored-server> --query state
   ```
   Connect from inside the VNet with `psql` and spot-check recent rows in the key application tables.
2. Create a private endpoint for the restored server, like `azurerm_private_endpoint.postgresql_pe`,
   linked to the `privatelink.postgres.database.azure.com` DNS zone.
3. Point the backend at the restored server by updating the database host secret in Key Vault,
   then restart the backend app so it picks up the change.
4. Run `python manage.py migrate --check` against the restored database to confirm the schema is current.
5. After the restore is confirmed, either bring the restored server under Terraform
   (`terraform import`) or move the data back to the primary server. That way the next
   `terraform apply` does not drift. Remove any temporary servers you no longer need.
